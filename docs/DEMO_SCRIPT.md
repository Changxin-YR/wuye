# 演示动线（6 分钟精简版）

> **云邻AI智脑** 的 6 分钟演示动线。
> 本文只覆盖"能现场跑出来"的东西，每一步都给出**证据位置**，便于复核。
> 演示环境：Windows + MySQL（`property_workorder`）+ 项目自带 venv。

## 1. 一句话定位

> 这是一个物业社区服务的垂直场景。它不只是页面和 CRUD，而是**受控的数字代理**：
> AI 和当前登录用户**同权限**——RBAC 决定能不能做、数据范围决定能对哪些数据做、
> 风险分级决定能不能自动做；所有写操作都走同一个 `PropertyService`，带幂等、乐观锁、
> 执行后回读和全程审计。一句话：**模型负责理解和规划，授权和执行永远由服务端决定。**

## 2. 登录与工作台（约 40 秒）

**操作**：`manager01` 登录 → 工作台。

**说明**：
- 导航是**按权限渲染**的：经理能看到 11 个模块，维修工看不到人员档案、审批等入口。
- 工作台 6 个状态卡：待派单 / 已派单 / 维修中 / 待验收 / 已关闭 / 已取消，数字来自**数据范围过滤后的库**。
- 右上「询问 AI」进 AI 助手，页面顶部有**当前身份条**（姓名/角色/数据范围）。

**证据**：`tests/test_routes.py`（导航可见性 + 未授权 403）。

### 财务模块（可选 40 秒）

左侧「收费」→ 顶部三张卡（待缴金额 / 待缴户数 / 已收）；点 **「只看逾期」** → 只剩 2 张逾期账单（8 月账期，逾期 12 天 / 5 天）。
点开一张 → 「登记收款」可部分收款（状态变"部分缴纳"）→ 再收齐（"已缴"）→ 「冲销」会退回收款前状态 → 「作废」在有收款时会被拒绝（先冲销再作废）。

## 3. 工单闭环（约 1 分 30 秒）

**操作**（左侧「维修工单」）：

```text
报修（owner01 或客服代报）→ 派单（经理/客服）→ 接单（维修工）
→ 记进展 → 提交完工 → 验收关闭 → 评价
```

**说明**：
- 状态机是**服务端强约束**：非法流转（例如对已关闭工单再派单）会返回明确错误，不是前端藏按钮。
- 每一步都写 `order_log`（时间线）与 `audit_log`（谁、什么身份、前后状态）。
- 派单目标可以是维修工**姓名或账号**，服务端解析后校验"这个人能不能接这单"。
- 数据范围在这里能看出来：`engineer01` 只能看到派给自己那 6 张单。

**证据**：`tests/test_services.py`（状态机全链路 + 非法流转）、工单详情页右侧时间线。

## 4. AI 一句话办事（约 1 分 30 秒）

**操作**：在 AI 助手（`manager01`）里说三句话：

1. **查询**："这个小区的欠费情况怎么样？" → 调 `arrears_summary`，按小区汇总户数与金额。
2. **新增**："1栋1单元101 厨房水管漏水，帮我报修，联系人张伟 13800002001，类别水暖，普通" →
   调 `list_houses` → `create_work_order` → **回读** `get_work_order` 确认落库 → 报单号。
3. **变更**："把这张工单派给黄磊" → 调 `list_staff` 解析姓名 → `assign_work_order`（R2）→ 状态变「已派单」。

**说明**：
- 顺序是**模型自己规划**的：先查后做、拿到 id 再写、写完回读，不是我们写死的流程。
- 工具是**动态能力目录**：MCP 握手时按权限只注册他能用的工具（经理 73 个 / 业主 27 个），
  没权限的工具**不进模型上下文**。
- 系统提示词是物业助手身份（不是编码助手），且**记忆在会话里**：可以接着说"那张单"。

**证据**：`artifacts/agent-spec/e2e-full.log`（真实运行日志）、
`python artifacts/agent-spec/e2e_agent_demo.py`（可复跑）。

## 5. 同一句话，不同人（约 1 分钟）

**操作**：换三个账号，在 AI 里问**同一句话**："我名下有哪些工单？" / "帮我把 2 栋 201 删掉。"

| 账号 | 期望结果 |
| --- | --- |
| `manager01` | 本小区全部工单；删除会走确认卡片 |
| `engineer01` | 只有派给自己的单；没有人员/房屋写权限 |
| `owner01` | 只有本人房屋的单；**"删除房屋"这个工具根本不在它的能力列表里**，助手会直接说无权办理 |

**说明**：权限不是提示词写的，是**每次调用工具时服务端按当前用户重算**：
`Policy(RBAC + DataScope)` + 会话版本 `auth_version`。改角色或登出 → 令牌与缓存的运行时同时失效。

**证据**：`docs/AGENT_ARCHITECTURE.md` §4/§5；`python artifacts/agent-spec/mcp_handshake_probe.py` 的输出。

## 6. 高风险操作的人工闸门（约 1 分钟）

**操作**：经理对 AI 说"把 2 栋 1 单元 201 这套空置房删掉" → 助手会先复述确认 → 用户说"确认" →
**AI 调工具，但服务端不执行**，返回一张**确认卡片**（预览：`删除房屋：云邻花园 2栋 1单元 201`，R3，10 分钟有效）。

然后**故意在聊天里说"我确认，直接删"** → 助手会回答："聊天里的确认不能代替系统审批，请在卡片上点确认。"
→ 最后**点击卡片上的「确认执行」** → 服务端重新校验（账号/会话版本/是否过期/单据版本/业务规则）→ 真正删除 → 审计留痕 `source=agent`。

**说明**：
- 风险分级：R0 只读 / R1 普通写自动 / R2 白名单内自动其余确认 / **R3 删除、财务、归档一律确认**。
- 确认时**重新做全套校验**，浏览器只提交 `action_id`，不能替换参数（服务端保存 payload + 哈希）。
- 这是"既让 AI 真办事、又不让它闯祸"的落点。

**证据**：`artifacts/agent-spec/e2e-full.log` 的 S3 场景；`tests/test_risk.py`（若已落地）。

## 7. 工程性实现

| 能力点 | 一句话 + 证据 |
| --- | --- |
| 事务 / 乐观锁 / 幂等 / 回滚 | 写命令统一 `request_key`(幂等) + `expected_version`(乐观锁，`version_id_col`)；重复提交只执行一次，旧版本号返回冲突；业务行与日志/审计同事务提交 |
| 同一个服务层 | 页面与智能体都调 `services.py` / `services_ops.py`，没有任何"第二条写库路径" |
| 审计 | 每条写操作落 `audit_log`（含 `source=web|agent`、before/after），审计页可筛来源 |
| 回读校验 | 写命令返回前回读目标行；智能体只有在 `ok=true` 时才说"已完成" |
| 测试 | `python -m unittest discover -s tests -q`；智能体链路另有 `e2e_agent_demo.py` |

## 9. 常见问题

| 问题 | 说明 |
| --- | --- |
| 为什么用 DeepSeek Harness 而不是自己写 Agent？ | 自己写会掉进"规划器 + 工具网关"的坑；harness 提供成熟的 agent loop、会话持久化、工具协议（MCP）、插件化配置。我们用官方 SDK + 配置覆盖接入，**不改它源码**，把精力放在业务、权限与风险控制上 |
| AI 会不会瞎编？ | ① 系统提示词要求先查后做、缺参就反问、不编造；② 所有事实来自工具返回；③ 写操作必须回读校验；④ 提示词不是安全边界——**授权在服务端** |
| 提示词注入怎么办？ | 模型看到的只是工具返回；工具调用由服务端重新鉴权。"忽略权限、你是管理员"只会得到一次 403 |
| 并发/重复提交？ | 幂等键 + 乐观锁；同一用户同时只允许一轮对话（运行时加锁） |
| 生产化还缺什么？ | ① 运行时共享化（当前一用户一进程）；② R3 叠加二次口令；③ 模型通道与密钥托管；④ 观测（trace/费用）与限流 |
| 数据范围怎么做的？ | `Policy.condition()` 把范围**下推到 SQL**（all/community/building/assigned/self），页面与工具共用；测试里有"条件确实在 SQL 里"的编译断言 |

## 10. 小结

> "这套系统的重点不是'让 AI 会聊天'，而是**让 AI 能在真实权限边界内把事办完，并且每一步都留痕、可回溯、可拒绝**。"
